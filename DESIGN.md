# go-intl

A pure-Go implementation of ECMA-402 internationalization, usable on its own and
as the base the go-quickjs engine builds `Intl` on.

## Why this exists

go-quickjs carries `internal/icu`: about 12,000 lines of Go and 14 MB of data
that answer every `Intl` service and agree with a full ICU on 7,948 of 7,949
golden cases. The behavior is excellent. The shape is not a library:

- The data is welded in with `go:embed` at package scope. There is no seam for a
  caller to substitute, trim or supply data, so importing it costs 14 MB.
- `RegisterDisplayNames(packed []byte, tags []string, blocks [][2]uint32,
  records [][3]uint32)` puts the binary layout in the public API.
- `Locale` is a thirty-field decoded number-formatting record, not a locale
  identifier, so there is no type for "a locale" to pass around.
- Process-wide `sync.Once` state and a global cache mean one configuration per
  process, with `WarmupIntlData()` as a global side effect.
- Dispatch is by string with `(T, bool)` returns rather than typed errors.

None of that is cosmetic, and all of it follows from one upstream fact.

## The root cause

The tables are generated by running node, calling `Intl.*`, and scraping the
**formatted output**. The data is ICU's *answers*, not CLDR's *rules*. So:

- Only what `Intl` exposes can be obtained, which is why the tables are shaped
  the way they are. CLDR's `windowsZones` is a worked example: it exists
  upstream, `Intl` never exposes it, and its absence was a live conformance
  failure until it was added from CLDR directly.
- A skeleton yields the pattern ICU *picked*, not CLDR's `availableFormats` plus
  the UTS #35 matching algorithm. The code memoizes decisions instead of making
  them.
- Regeneration needs a node binary of the right ICU version.

A lookup table of answers cannot be refactored into a library. The pipeline is
what has to change first; the architecture follows from it.

## What is kept and what is replaced

| | |
|---|---|
| **Replaced** | The architecture: data access, API shape, state model, the generator's source |
| **Kept** | The algorithms and the validation corpus - years of accumulated correctness |

ICU4X is the model for the architecture, not a source to port. Of ~183,000
non-comment lines of Rust across the crates ECMA-402 needs, the architecture is
`provider/core`, `locale_core`, `locale_fallback`, `writeable` and `tinystr` -
about 24,000 lines, 13%. In Go it is smaller still, because every ULE, VarULE,
Yoke and ZeroFrom derive exists to make borrowed deserialization sound under
Rust lifetimes and has no Go counterpart. The remaining 87% is algorithms and
zero-copy machinery we either already have or do not need.

ICU4X's own ECMA-402 binding covers two of nine services, and its
`DateTimeFieldBag` - the runtime option bag ECMA-402 needs - is a stub marked
"TODO: Add an example when more fully implemented". Porting it would land behind
where go-quickjs already is.

## Layers

```
  API        intl.NumberFormat, intl.DateTimeFormat, intl.Collator    ECMA-402 shaped
  Algorithms UTS #35 pattern selection, UCA, plural rules, UAX #29    the logic
  Model      typed data: patterns, rules, tries, tables               no answers
  Provider   Source interface - embedded / io.FS / custom             the seam
  Datagen    CLDR-JSON + icuexportdata + ICU data + UCD to Model      offline
```

**The invariant: datagen emits inputs to algorithms, never answers.** If a
generated table holds a string a formatter could have produced, the layering has
been violated. This one rule is the difference between a library and a memo pad.

## Data sources

The upstream inputs, which are what ICU4X's `provider/source` takes plus two
it does not:

| Source | Feeds |
|---|---|
| `unicode-org/cldr-json` releases | numbers, dates, units, names, plurals, zones |
| `icuexportdata` (tagged release) | UCA and collation tailorings; later properties, casemap |
| ICU's data sources (`icu4c-*-data.zip`) | the collation tree and what the export drops from tailorings |
| Unicode Character Database | normalization |
| IANA tzdb | zone rules |
| ICU's compiled data (`icudt78l.dat`) | the break rules and dictionaries, as ICU compiles them |

`icuexportdata` is produced by ICU4C tooling, so this does not fully escape
ICU4C - but it is a versioned, tagged, declarative export of *rules and tables*,
not a scrape of a running engine's formatted output. That distinction is the
whole point.

Every source is pinned, and the pins are anchored to **ICU 78.3** - the ICU that
produced the golden corpus, hence CLDR 48.0 and Unicode 17.0. Generating from a
release the oracle was not built with turns upstream drift into corpus
differences that look like bugs. [SOURCES.md](SOURCES.md) is the record; each
generated file repeats its own source's version in its header.

ICU4C keeps one further role: **test oracle**. `golden.mjs` stays; `extract.mjs`
goes.

## Public API

One package, types mirroring the `Intl` namespaces, Go idiom throughout.

```go
type Locale struct {
    Language   Language // fixed-size, comparable
    Script     Script
    Region     Region
    Variants   []Variant
    Extensions Extensions // -u-ca-, -u-nu-, -u-co-
}

func ParseLocale(s string) (Locale, error)

type Source interface {
    Open(marker Marker, loc Locale) (Payload, error)
}

func NewNumberFormat(loc Locale, opts NumberFormatOptions) (*NumberFormat, error)
func NewNumberFormatFrom(src Source, loc Locale, opts NumberFormatOptions) (*NumberFormat, error)

func (f *NumberFormat) Format(v Number) string
func (f *NumberFormat) AppendFormat(dst []byte, v Number) []byte
func (f *NumberFormat) FormatToParts(v Number) []Part
func (f *NumberFormat) ResolvedOptions() ResolvedNumberFormat
```

Rules:

- Options are structs whose zero value is the ECMA-402 default.
- Constructors return `error` where JS throws `RangeError`. No `(T, bool)`.
- Formatters are immutable after construction and safe for concurrent use. No
  global `sync.Once` graph, no `Warmup` functions.
- Data is injected with a package default; the `From` variants take a `Source`.
  A caller needing `en` only embeds kilobytes.
- `FormatToParts` is mandatory, not optional. Parts cannot be produced from a
  memoized string, so it is the constraint that keeps the algorithm layer honest.
- `SupportedLocalesOf` becomes `Supported(want []Locale, opts) []Locale` over the
  real fallback chain.

Do **not** port ICU4X's `DataMarker` const-generic dispatch. It exists because
Rust needed compile-time keys; Go's answer is narrow typed provider interfaces.

## Compatibility profiles

Node and ICU4C divergences are a construction-time profile, not ambient state
and not a go-quickjs concern:

```go
type Compat int

const (
    Standard Compat = iota // ECMA-402 as written
    NodeICU                // node/ICU4C observable behavior
)
```

go-quickjs's current quirk set is small and enumerable - proleptic Islamic era
names, Japanese `h12` preference, Temporal era and hour-cycle handling, about six
sites. Every quirk is a named, documented divergence with a test on both sides.

**If the list passes roughly twenty entries, standards mode is wrong somewhere
and the profile is hiding it.** That is a tripwire, not a budget.

"Exactly like node" is definable only against a pinned ICU version and a corpus.
Record the version in the golden file header; corpus-exactness is the
operational definition.

## Testing

Two suites, testing different things. Much of test262's intl402 is about JS
binding semantics - coercion order, getter sequence, `RangeError` versus
`TypeError`, property enumeration - which cannot be meaningfully asserted about
a Go library.

| Suite | Lives in | Tests |
|---|---|---|
| Golden corpus, locale, fallback, collation, segmentation | **go-intl**, Go | i18n behavior |
| test262 intl402 | **go-quickjs**, JS | binding semantics |

The bridge already exists: `golden.mjs` emits `{source, value}` pairs - pure
data. The same corpus replays natively in Go and unchanged in JS. One artifact,
both suites. Port the data-driven subset of intl402 into the Go corpus; leave the
semantics tests where they are.

## Non-goals

- Porting ICU4X's source, its zero-copy machinery, or `databake`.
- cgo, wasm, or a C toolchain. go-quickjs's portability rule applies here.
- Bug-for-bug emulation of all of ICU4C. Only the enumerated profile.
- API stability before the services exist. v0 until proven.
